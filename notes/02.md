# D2 学习清单

## 必答（用自己的话）
1. validate 和 execute 的区别是什么？为什么 validate 能"不打 DB 就拦截"？
    validate是本地网关，不接触mysql，再执行mysql前进行一次检查，用的是本地的sqlglot，execute是执行器，
接触mysql，真实执行mysql看结果反馈，validate能不打DB就拦截是因为在打DB之前就进行了本地网关的检查，发现一
些执行前就暴露的问题。
2. 为什么需要两次 validate？只有一次会怎样？
    两次validate来同时验证执行前拦截和自纠错，只有一次没办法单独验证这两项。
3. loop 的重试刹车是什么？超了预算走哪条分支？
    重试刹车是budget_ok(check_budget)看看预算是否充足，如果没有预算，直接停止。走的是refuse/fail路线。
4. blocked=True 和 blocked=False + observation 的区别是什么？各对应什么动作？
    blocked=True代表直接安全拒绝，blocked=False + observation是有可观测的问题，要进入reflect反思然后进行重新执行。
5. 为什么 errno → kind 只算一次？两层各算一次会出什么问题？
    只观测一次能保证一致性和权威性，两层各算一次会出现两次结论不一致的情况，然后导致后续的程序分支混乱，只在
errno观测产出后算一次，并且以这次为准。
6. token 计数为什么要累加在 client 实例上？budget_ok 怎么用它？
    token计数累加在client实例上是因为一个用户可能调用多次llm请求，budget_ok在每次调用之前进行一次检查，
检查输入token+输出token的总和累计是否大于budget，大于走refuse分支，否则正常调用。
