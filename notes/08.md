## 一、核心分层：Pydantic 只管「系统边界」，中间状态用 TypedDict

**一句话结论：**

> `BaseModel`：对外**出入口（边界）**——强校验、可序列化。
> `TypedDict`：流程**内部状态（中间态）**——只做类型提示，不校验，支持 LangGraph 的增量合并更新。

### 1. 什么是「系统边界」

就是程序和**外部世界交互**的地方：

- HTTP 接口的入参、出参（FastAPI 的 request / response）
- 读取配置文件、环境变量（`Settings`）
- 读取磁盘文件、接收消息队列消息
- 对外输出的返回体

这些数据来自外部，**不可信**，必须做：类型校验、自动类型转换、校验失败直接拒绝脏数据、方便序列化成 JSON / 从 JSON 解析。这正是 `BaseModel` 的强项。

```python
# 边界示例：接口请求体
from pydantic import BaseModel

class QueryRequest(BaseModel):
    query: str
    top_k: int
```

请求进来，Pydantic 自动校验 `top_k` 是不是整数、`query` 是不是字符串，不合格直接 422。

### 2. 什么是「中间状态」AgentState

Agent 在推理循环里流转的状态，**只在程序内部**、LangGraph 图节点之间传递：历史消息、检索结果、当前思考、工具返回、是否结束标记……

LangGraph 的核心语义是**部分更新（partial update）+ 自动合并**：

```python
from typing import TypedDict, List

class AgentState(TypedDict):
    messages: List
    retrieved_docs: List
    thought: str
```

节点返回 `{"thought": "我要去检索文档"}` 时，它**只更新 `thought` 字段，其余字段保留**，自动合并进去。

### 3. 为什么 AgentState 不用 BaseModel

| 原因 | 说明 |
|---|---|
| **① BaseModel 是整体替换，不是增量合并** | Pydantic 模型是完整对象，传部分字段要么缺字段报错、要么覆盖整个实例；想实现 LangGraph 的局部字段更新得自己写合并逻辑，很麻烦。而 LangGraph 原生对 TypedDict 做了适配，「返回部分字段、增量合并」就是它的设计目的。 |
| **② 校验 & 序列化开销** | Agent 循环跑很多轮，每步节点都读写 state。若 state 是 BaseModel，每次更新都触发校验/类型检查，高频循环下是不必要的性能损耗；TypedDict **只是静态类型提示（给 IDE / mypy 看），运行时零开销**。 |
| **③ TypedDict 是 dict 兼容的** | LangGraph 底层把 state 当字典处理，TypedDict 本质就是带类型注解的 dict；BaseModel 是对象，来回要 `.model_dump()` / `.model_validate()` 转字典，增加样板代码。 |

### 4. 工程小结（贴合 LangGraph + FastAPI 项目）

| 类型 | 本项目中的用途 | 特点 |
|---|---|---|
| `BaseModel` | `QueryRequest` / `QueryResponse` / `Settings` / `EvalCase` | 边界校验、序列化、可加 `repr=False` 保护密钥 |
| `TypedDict` | `AgentState`（D2 已建） | 内部状态、LangGraph 增量合并、无运行时开销 |

> 文档 §11.1 明确分层：系统边界（HTTP I/O、文件、配置）用 `BaseModel`；中间状态（AgentState）用 `TypedDict`。

## 二、Pydantic 字段校验

### 1. `Field(repr=False)` 防止密钥泄露

```python
from pydantic import BaseModel, Field

class Settings(BaseModel):
    llm_api_key: str = Field(default="", repr=False)
    model_name: str = "gpt-4o"
```

**`repr` 是什么**：`repr()` 是 Python 内置函数，拿到对象的「开发者字符串表示」。`print(settings)` 底层等价于 `print(repr(settings))`。Pydantic 打印模型时，按字段的 `repr` 参数决定要不要把该字段放进打印串：

- `repr=True`（默认）：打印时展示该字段
- `repr=False`：打印 / 日志输出 repr 串时**跳过该字段，不输出值**

**效果对比：**

```python
settings = Settings(llm_api_key="sk-xxxxsecretkey", model_name="gpt-4o")
print(settings)
# repr=False 后输出类似：Settings(llm_api_key='...', model_name='gpt-4o')
# 不会把 sk-xxxxsecretkey 明文打出来！
```

**⚠️ 重要边界（很多人踩坑）：**

1. **只防 `repr` / `print`，不防 `model_dump()` / `model_dump_json()`**。要禁止序列化输出，需额外加 `exclude=True`：

   ```python
   llm_api_key: str = Field(default="", repr=False, exclude=True)
   ```

   `exclude=True` 才会让 `.model_dump()` 默认排除该字段。

2. **最怕的场景**：调试时随手 `print(settings)`，把 API Key、数据库密码明文打进控制台/日志文件。`repr=False` 是低成本的防护，属于基础安全习惯。适合配置类 `Settings`（Pydantic Settings）。

3. **不是加密！** 只是不打印，值仍在内存里、代码里照常可用。`print(settings.llm_api_key)` 单独打印属性仍会输出明文。

> 重点：它控制的是「模型对象整体打印」，不是禁止访问字段本身。

### 2. `Literal` 限定枚举，拼错即报错

```python
FinalStatus = Literal["success", "refused", "failed"]
```

比 `str` 好：IDE 自动补全、拼错时 Pydantic 直接拒绝、自文档化。

### 3. `Field(ge=0, le=2)` 数值上下界

```python
max_retries: int | None = Field(default=None, ge=0, le=2)
```

- `default=None`：默认不填
- `ge=0`：Greater than or Equal，必须 ≥ 0
- `le=2`：Less than or Equal，必须 ≤ 2

**作用**：用户传 `max_retries=5` 时，Pydantic 直接拦截并返回 422，保护后端不收到越界参数（防止 `max_retries=100` 把服务器刷爆）。

### 4. `default_factory`：每个对象一份新默认值

```python
options: QueryOptions = Field(default_factory=QueryOptions)
```

`options` 字段本身是个对象（`QueryOptions`）。如果写 `= QueryOptions()`，**所有请求会共享同一个 `options` 对象**——用户 A 改了参数，用户 B 也受影响。用 `default_factory=QueryOptions` 保证每个新请求都生成一份崭新配置。

同理 `default_factory=datetime.utcnow`：每次创建对象时才生成时间，**不加括号是因为传的是函数本身**（不是调用结果）。

## 三、`@field_validator` + `@classmethod`：入参清洗与校验

### 1. 一句话总览

- `@field_validator`：**Pydantic 的字段校验 + 清洗装饰器**
- `@classmethod`：Python 原生装饰器，标记方法是**类方法**，第一个参数是类本身 `cls`，不是实例 `self`

本项目用途：对入参 `question` 做两件事——① 清洗（首尾去空格 `.strip()`）；② 校验（检测非法控制字符，有就抛异常拦截脏输入）。

> Pydantic v2 里 `@field_validator` **要求校验器方法必须是 classmethod**，所以两者总是成对出现。

### 2. `@classmethod` 基础（Python 原生）

| 方法类型 | 定义 | 第一个参数 | 调用方式 |
|---|---|---|---|
| 实例方法 | `def func(self, ...)` | 实例对象 `self` | 需先 `obj = Model(...)` |
| **类方法** `@classmethod` | `def func(cls, ...)` | 类本身 `cls` | 直接用类调用，不用 new |
| 静态方法 `@staticmethod` | `def func(...)` | 无默认首参 | 与类、实例弱绑定 |

```python
class Demo:
    @classmethod
    def hello(cls):
        print(f"我属于类：{cls}")

Demo.hello()   # 直接用类调用
```

**为什么 Pydantic field_validator 强制要求 @classmethod**：Pydantic 解析原始输入（dict/json）时，**对象实例还没创建完成**——它先拿原始数据跑校验器，通过后才构造实例。此时不存在 `self`，只能传类 `cls`，所以必须 `@classmethod`。

> 坑点：写 `field_validator` 不加 `@classmethod` 会直接报错。

### 3. `@field_validator("question")` 是什么

```python
from pydantic import BaseModel, field_validator

class QueryRequest(BaseModel):
    question: str

    @field_validator("question")
    @classmethod
    def clean_question(cls, value: str):
        # 1. 清洗：去掉首尾空格
        value = value.strip()

        # 2. 校验：检查有无控制字符（乱码、不可见字符）
        import string
        if any(c in string.control for c in value):
            raise ValueError("问题包含非法不可见控制字符")
        return value
```

**Pydantic 处理流程：**

1. 收到原始输入（HTTP json / dict）
2. 按字段拿到原始值
3. 触发绑定在该字段上的 `field_validator`
4. 你在函数里**修改清洗这个值，或抛异常拒绝**
5. `return` 出去的值，才是这个字段的最终值
6. 所有校验通过，模型实例构建完成

> ✅ 它既是校验器，也是清洗转换器：
> - 抛异常 = 拦截请求，返回 422
> - `return` 修改后的值 = 完成字段清洗（strip、替换字符、转小写等）

**`mode` 两种模式（很关键）：**

| mode | 时机 |
|---|---|
| `mode="before"` | 在 Pydantic 类型转换**之前**拿到原始值 |
| `mode="after"`（默认） | Pydantic 先转成目标类型（str）**之后**，再交给你校验清洗 |

本场景 `question` 是字符串、要 strip + 查字符，用默认 `after` 最合适。流程：原始数据 → Pydantic 转成 str → 传给你的校验函数清洗校验 → 存入字段。

### 4. 逐行拆解业务代码

1. `@classmethod`：告诉 Python，第一个参数 `cls` 是 `QueryRequest` 这个类，不是实例
2. `@field_validator("question")`：注册钩子，监听 `question` 字段
3. `value`：已经转好类型的 question 字符串
4. `.strip()`：清洗。`"   什么是agent？   "` → `"什么是agent？"`（前端复制粘贴、输入法、换行常带多余空格）
5. 控制字符检查：`\t \n \r` 这类不可见控制字符（ASCII 0–31），常是复制乱码、注入、隐藏恶意字符；发现就 `raise ValueError` → Pydantic 捕获 → 接口返回校验失败
6. `return value`：**必须 return！** 不 return 字段会变成 `None`

> 重点区分：
> - **清洗逻辑**：修改 value、return 新值（strip、脱敏）
> - **校验逻辑**：满足坏条件 → raise 异常，拒绝数据

## 四、零散工程概念（一句话速记）

### schema vs schemas

- `schema/schema_catalog.yaml`：给**大模型读**的表结构（数据结构定义）
- `sqlpilot/schemas/`：给**前端读**的请求 / 响应格式（Pydantic 模型）

### 单例模式（Singleton）和连接池

为什么 `QueryService` 要做成全局变量？因为里面有个**数据库连接池**。如果每次请求都新建一个连接池，数据库直接被打挂。

### FastAPI 和 TestClient

- **FastAPI**：接收 HTTP 请求，映射到 Python 函数
- **TestClient**：不启动服务器也能模拟发请求，用来写自动化测试

### CI（持续集成）

在云端自动跑测试的「监工」。
