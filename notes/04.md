1.为什么 KEYWORD_HINTS 挪到 synonyms.yaml？ 至少 2 条，其中一条和评测控制变量有关
    因为原先的keyword_hints是硬编码，每次进行修改需要去源码进行修改，第二个原因是
synonyms.yaml可以控制评测数据变量，通过yaml的version: v1控制，能写进评测报告当
控制变量，硬编码在代码里，没办法说“我这次用的是哪个版本的同义词”，D11调优改了同义词，
报告里要写SYNONYM_VERSION=V1还是V2，只有文件能标版本，代码不行。

2.“销售额”召回 orders，走的是 bigram / 同义词 / 精确表名 哪几条？
    销售额召回orders，走的是bigram+同义词，分别是5/10。精确表明没有生效，用户直接
问“orders表中有多少行”这种带表名的问法才会触发。
3.“供应商”为什么返回 []？哪一行代码保证的？ 没这个过滤，D6 E10 会怎样？
    因为我们的同义词yaml中没有供应商字段，代码行是：
```aiignore
matched_synonyms = [s for s in self.synonyms if s in question]
if not matched_synonyms:
    return [ ]
```
D6 E10：{"id":"E10","question":"哪个供应商的供货金额最高？",
"layer":"不可回答","gt_sql":null,"expect":"refuse","tags":["幻觉控制"]}
这是一道不可会答题：库里没有供应商表，正确行为是拒答。如果retriever返回了suppliers
(decoy表)，模型可能会按照suppliers写sql，幻觉出一个答案————这就是“幻觉控制”失败。
返回[]——generate_sql没schema可写——返回refuse，这才是正确路径。
4.Only in G1 = [] 证明什么？ 如果它不是 []，D11 消融还能做吗？
    G0是G1的子集，唯一差异是表数量，所以消融能成立。Only in G1 = [] 说明
没有“G1有、G0没有”的表，所以模板完全一致，单变量成立。
    证明G1对比G0没有对应的多余的东西，所有的变量都在G0，G0多的是表的数量，
如果不是[]，证明还有其他的变量，不能说明这是严格的表数量带来的影响，消融实验
就不能做了。
5.明天加“月收入 → orders”，改哪些文件？改代码吗？
    需要改的是synonyms.yaml文件，不需要改代码。
    这就是把数据抽出来的好处——D11调优只动YAML，代码不动，评测可复现。

# D4 基础三题

## 1. TypedDict 的 total=False

- `TypedDict` = 给 dict 加"字段说明书"，运行时还是普通 dict，不做任何检查
- `total` 是**类定义的开关**，默认 `True`（所有字段必填），`total=False` = 所有字段可选
- 这个项目用 `total=False`，是因为 LangGraph 节点只返回"部分字段"，`total=True` 会报"缺字段"
- 类型注解**只影响类型检查器（IDE/mypy），不影响运行时**

## 2. @lru_cache

- 缓存的是"**函数参数组合 → 返回值**"的映射
- 默认 `maxsize=128`：最多存 128 个不同参数组合，超了淘汰"最久未使用"的（LRU）
- `get_catalog()` **无参数**，只有 1 种组合（空），永不淘汰
- 实测：首次 32.8ms（读 YAML + 建索引），第二次 1.0ms（查缓存），`a is b → True`（同一对象）

## 3. 加类型注解的实践

- `def _budget_ok(state: AgentState, s: "Settings") -> bool:`
- `Settings` 加引号是"延迟求值"，避免循环 import 报 NameError
- 加完跑 `python -m sqlpilot.agent.loop_fallback`，**行为不变**（10 步 success）
- 证明：类型注解是"说明书"，不是"运行时逻辑"
