## 今日核心概念（已讲透）

1. **`from __future__ import annotations`**：注解只当字符串存、运行时不求值，兼容 `X | None` 新写法。注意：它不是「延迟类型检查」。
2. **Streamlit 心法**：脚本从上到下 = 页面从上到下；`st.xxx` 多靠副作用「画」，不返回值。
3. **重跑机制**：每次交互整段脚本重跑 → 普通变量被重置；`st.session_state` 是跨重跑存活的「便签板」。
4. **控件两类**：
   - 输入类（`button` / `text_area` / `selectbox`）→ 返回你要的值
   - 展示类（`markdown` / `error` / `success` / `code` / `dataframe`）→ 返回 `None`，只画
5. **`with` 切换画板**：`st.sidebar` / `st.expander` / `st.spinner`。
6. **`@st.cache_resource`**：缓存重对象（连接池 / 模型）；直连时代码必须用它。走 HTTP 后 UI 无重对象 → 不再需要。
7. **`st.set_page_config`**：`page_title` = 浏览器标签栏文字（已验证生效）；`layout="wide"` = 主区全宽；必须第一个 `st` 命令。

## 代码与任务清单不符的坑（重要）

1. `service.query()` 返回的是 **dict** 不是 `QueryResponse`；无 `result` 键，直连时是 `exec_result`。
2. `exec_result` 可能为 `None`（被拒 / 失败），取 `["rows"]` 前必须判空，否则 `TypeError`。
3. `trace` 是 dict 列表，用 `t['step']` 不是 `node.step`（否则 `AttributeError`）。
4. 【HTTP 改造后】外层键从 `exec_result` 变成 `result`（响应模型字段名）；`answer` / `sql` / `final_status` / `failure_reason` / `trace` 同名不变。

## 架构改造：直连 vs HTTP

- **改造前**：UI 直连 `QueryService`（UI 进程内 new，含 DB 连接池 + LLM key）→ 凭据暴露、与后端耦合。
- **改造后**：`UI --HTTP(httpx)--> FastAPI /api/v1/query --> QueryService --> DB`；凭据只在后端。
- **关键改动**：删 `import QueryService` + `cache_resource`；加 `httpx.post` + `call_api()`；`exec_result`→`result`；异常处理 `httpx.ConnectError` / `HTTPStatusError`。
- **启动顺序**：先 `python -m uvicorn sqlpilot.api:app --port 8000`，再 `streamlit run`。
- **一句话**：表现层只依赖接口，不依赖实现 = 分层架构核心。

## 错题本 / 盲点

1. 【参数 vs 返回值】展示类控件返回 `None` 只画；输入类才返回要用的值。（已纠正，需复习）
2. 【NoneType 崩】取嵌套字典前必须判 `None`。
3. 【PowerShell curl】PS 里 `curl` 是 `Invoke-WebRequest` 别名，不认 `-H` / `-d`；改用 `Invoke-RestMethod`、Git Bash 真 curl 或 Swagger。
4. 【连接复用 10054】后端停掉时旧 keep-alive 连接被重置 → `WinError 10054`；属正常解耦现象，已成为「UI 真走 HTTP」的证据。

## 面试加分（今日）

- **分层架构**：表现层依赖接口不依赖实现；UI 走 HTTP、凭据只在后端、可独立部署扩缩容。
- **顺利路径 vs 自纠错路径**：顺利 = validate 一次 pass；纠错 = generate → validate 失败 → check_budget → reflect → regenerate。用压力集失败样本统计 retry 后成功率，来证明纠错价值。
- **拒答 / 幻觉控制**：不可回答题（缺列 / 空表 / 无数据）应拒答而非编 SQL；评测集需含失败 / 边界样本，否则测不出能力。
