# D3 学习清单

## 必答
1. LangGraph 的四个概念是什么？各对应手写版的什么？
    state,node,edge,conditional edge,
    state对应手写版返回的dict，node对应的是 每一个状态更新的节点？edge对应的是执行顺序，
conditional edge对应的是if判断。
2. 为什么节点要"返回 dict"而不是"原地改 state"？原地改会出什么问题？
    返回dict这是做一个声明，没有实际修改，最后框架统一apply，每一步都可追溯，防覆盖，原地改不方便追溯。
3. 路由函数（route_*）为什么只能返回字符串、不能改 state？所以哪些字段必须由节点写进 state？
    这个不是很清晰，路由函数只能返回字符串，因为有一些变量是局部变量，不能做一个全局的覆盖，所以类似的passed，blocked？？必须由节点写入state
    答案：
    LangGraph 的设计：路由函数（route_*）在运行时被调用，只读 state，返回一个字符串，框架根据字符串查映射表，决定下一步走哪个节点。
    为什么不允许改 state：
    职责分离：节点负责"生产状态"（写 passed/blocked/budget_ok），路由负责"消费状态"（读它们决定方向）。如果路由也能写，那"谁改了 state"就说不清，调试时找不到源头。
    可测试：路由是纯函数（输入 state，输出字符串），可以单独测。如果它能改 state，测试就要 mock 一堆东西。
    可预测：路由的返回值就是"下一步去哪"，没有副作用。如果它能改 state，可能改完之后目标节点读到的是"被路由改过的 state"，行为不可预测。
    所以哪些字段必须由节点写进 state：所有路由函数要读的字段。具体到项目里：
    
    路由函数	读什么	谁写
    route_guard	blocked, passed	validate_sql 节点
    route_exec	exec_result.ok, error.kind	execute_sql 节点
    route_budget	budget_ok	check_budget 节点
    route_reflect	need_relink	reflect 节点
    一句话：路由读什么，节点就得写什么。这是"节点生产、路由消费"的契约。
4. D3 的 DoD 是什么？怎么证明 LangGraph 版和手写版行为一致？
    DoD是把昨天的手写版流程全部替换成langgraph，证明方法是运行一次，保证最后的结果一致，包括步数、重试次数、计数等。

START → retrieve schema → generate sql → nodes.route_gen（三岔口：pass/recover/block）
     → route_exec → ?（三岔口：success/retry/give_up）
     → route_budget（二岔口：reflect/refuse）
     → route_reflect（二岔口：relink/regenerate）
     → summarize/refuse → END

节点  	        路由函数	            返回值 → 目标节点

execute_sql	    route_exec	        success → summarize；retry → check_budget；give_up → refuse
check_budget	route_budget	    reflect → reflect；refuse → refuse
reflect	        route_reflect	    relink → retrieve_schema；regenerate → generate_sql
